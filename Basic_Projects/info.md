# 多品类应用矩阵产品需求稿（V0.1）

## 一、项目概述

### 1.1 项目名称

多品类应用矩阵平台（暂定名：App Matrix）

### 1.2 项目背景

计划持续研发并运营 100 个以上不同品类的移动应用，覆盖工具、效率、内容、教育、健康、生活、娱乐等方向。

如果每个应用独立建设账号、支付、订阅、广告、埋点和运营能力，会产生较高的研发与维护成本。因此需要建设一套“公共能力平台 + 品类模板 + 单应用配置”的产品体系，使新应用能够快速上线，并通过数据验证持续迭代。

### 1.3 产品目标

- 支持 100+ 应用的快速创建、配置、发布和运营。
- 统一支付、订阅、广告、账号、埋点和远程配置能力。
- 根据不同品类灵活组合免费、订阅、买断、广告等商业模式。
- 建立从获客、激活、体验、付费到留存的完整数据闭环。
- 降低单个应用的开发、运营和维护成本。
- 支持低成本试错，快速淘汰低潜力产品、放大高潜力产品。

### 1.4 核心原则

1. 公共能力平台化，业务体验差异化。
2. 商业化模块可配置，不硬编码到单个应用。
3. 用户先体验价值，再触发付费。
4. 广告不得破坏关键任务流程。
5. 每个应用独立核算收入、成本和留存。
6. 默认满足应用商店、支付、广告和隐私合规要求。

---

## 二、产品范围

整体分为三层：

| 层级 | 主要内容 |
|---|---|
| 公共能力层 | 账号、支付、订阅、广告、埋点、推送、远程配置、实验、风控 |
| 品类模板层 | 工具类、内容类、教育类、健康类、娱乐类等标准模板 |
| 单应用业务层 | 品牌、页面、文案、核心功能、定价、权益和运营策略 |

首期建议优先覆盖以下品类：

- AI 工具：写作、图片、翻译、总结、扫描。
- 效率工具：待办、笔记、文件转换、日历、习惯管理。
- 图片视频：滤镜、抠图、压缩、格式转换、字幕。
- 教育学习：题库、语言学习、记忆卡、儿童启蒙。
- 健康生活：饮水、睡眠、健身、饮食记录。
- 实用工具：计算器、测量、单位换算、设备工具。
- 内容娱乐：壁纸、故事、音效、测试、轻互动。

首期不建议进入医疗诊断、证券投资、借贷、博彩等高合规风险品类。

## 三、用户角色

### 3.1 应用用户

- 游客用户：未注册，可以体验基础功能。
- 免费用户：已注册，使用受限功能或广告版本。
- 试用用户：处于订阅免费试用期。
- 订阅用户：拥有周期性高级权益。
- 买断用户：永久拥有指定权益。
- 流失用户：曾付费但已取消、过期或退款。

### 3.2 内部用户

- 超级管理员：管理平台、权限和全局配置。
- 产品运营：创建应用、配置功能、权益和活动。
- 商业化运营：配置价格、订阅、广告和付费墙。
- 内容运营：维护内容、素材和推荐位。
- 数据分析人员：查看指标和实验结果。
- 客服人员：处理订单、权益、投诉和用户反馈。
- 开发与测试人员：维护版本、环境和发布状态。

## 四、核心业务流程

### 4.1 新应用创建流程

选择品类模板  
→ 填写应用基础信息  
→ 选择功能模块  
→ 配置免费与付费权益  
→ 配置订阅和广告策略  
→ 接入埋点与远程配置  
→ 生成测试版本  
→ 商店审核  
→ 灰度发布  
→ 数据验证  
→ 扩量、调整或下架

### 4.2 用户核心流程

广告或商店进入  
→ 新用户引导  
→ 快速体验核心功能  
→ 获得首次有效结果  
→ 保存、导出或继续使用  
→ 触发次数限制或高级需求  
→ 展示付费墙或激励广告  
→ 完成支付  
→ 解锁权益  
→ 持续使用与续订

## 五、功能需求

## 5.1 应用管理中心

### 功能要求

- 创建、复制、停用和归档应用。
- 配置应用名称、图标、包名、商店信息和隐私协议。
- 选择应用所属品类及模板。
- 配置品牌色、字体、启动页和基础导航结构。
- 配置功能开关和模块排列顺序。
- 区分开发、测试、预发布和生产环境。
- 管理 iOS、Android 及不同渠道版本。
- 查看各应用版本状态和发布记录。

### 应用状态

- 草稿
- 开发中
- 测试中
- 待审核
- 灰度发布
- 正式发布
- 暂停运营
- 已归档

---

## 5.2 账号与用户体系

### 基础能力

- 支持游客模式。
- 支持 Apple、Google、手机号及邮箱登录。
- 支持账号绑定、解绑和注销。
- 支持多设备登录和权益恢复。
- 支持游客数据在注册后迁移。
- 支持设备 ID、账号 ID、订单 ID 的关联。
- 支持用户封禁、风险标记和异常行为识别。

### 账号策略

原则上降低注册门槛：

- 首次打开不强制注册。
- 用户保存云端数据、跨设备同步或付费时提示注册。
- 已付费但未登录的用户可通过“恢复购买”找回权益。

---

## 5.3 功能配置与体验系统

每个应用至少划分四类功能：

| 功能类型 | 说明 |
|---|---|
| 核心功能 | 用户下载应用的主要目的 |
| 辅助功能 | 提高完整度和使用效率 |
| 高级功能 | 用于订阅或买断转化 |
| 运营功能 | 签到、任务、推荐、分享、活动等 |

### 体验要求

- 新用户应在最少步骤内体验核心价值。
- 非必要情况下不在启动时强制登录或付费。
- 首次体验过程应提供示例数据或演示素材。
- 核心操作必须具有加载、成功、失败和重试状态。
- 未完成内容应支持草稿保存。
- 高风险操作必须二次确认。
- 无网络、弱网络及服务不可用时提供明确提示。
- 付费功能应展示权益说明，不只显示“不可使用”。

### 免费额度

支持以下限制方式：

- 每日使用次数
- 每月使用次数
- 累计免费次数
- 导出次数
- 文件大小
- 内容长度
- 分辨率或清晰度
- 高级模板数量
- 云存储空间
- 处理速度或队列优先级

所有额度应支持后台配置和分群实验。

---

## 5.4 支付系统

### 支付类型

- 单次购买
- 消耗型商品
- 永久买断
- 周订阅
- 月订阅
- 季度订阅
- 年订阅
- 免费试用
- 首期优惠
- 限时优惠

### 支付能力

- 对接 Apple App Store 和 Google Play 应用内购买。
- 根据业务需要接入 Web 支付，但必须遵循平台支付政策。
- 服务端验证支付凭证。
- 记录支付成功、失败、取消、退款和撤销。
- 支持补单和恢复购买。
- 订单状态与用户权益自动同步。
- 支持订单查询与客服备注。
- 支持不同国家、币种和税务显示。
- 支持价格本地化和商店价格映射。

### 异常处理

- 支付成功但权益未到账：自动重试并允许用户手动恢复。
- 重复回调：订单处理必须幂等。
- 退款或撤销：按规则回收权益。
- 网络中断：保留支付状态并在恢复网络后验证。
- 订阅宽限期：根据商店状态决定权益是否继续生效。

---

## 5.5 订阅系统

### 订阅权益

每个应用可独立配置权益，例如：

- 移除广告
- 无限使用核心功能
- 解锁高级模板
- 提高导出质量
- 提高处理速度
- 增加云存储空间
- 跨设备同步
- 专属内容
- 提前体验新功能
- AI 点数或月度额度

### 付费墙

支持以下展示场景：

- 首次启动引导结束后
- 用户首次获得有效结果后
- 免费次数用尽时
- 点击高级功能时
- 导出或保存时
- 使用一定天数后
- 活跃用户专属优惠
- 订阅即将到期或已流失时

### 付费墙配置

- 标题、副标题和权益列表。
- 套餐顺序及默认选中项。
- 原价、优惠价和折算价格。
- 试用期限及续费说明。
- 主按钮和关闭按钮。
- 用户评价、案例或效果展示。
- 服务条款、隐私政策及恢复购买入口。
- A/B 测试版本。
- 展示频控。

### 订阅管理

- 查看当前套餐、状态和到期时间。
- 跳转至系统订阅管理页面。
- 恢复购买。
- 展示取消订阅方法。
- 到期前提醒。
- 订阅失败和扣款重试提醒。
- 取消后收集原因，但不得阻碍取消。

---

## 5.6 广告系统

### 广告形式

- 开屏广告
- 横幅广告
- 插屏广告
- 原生广告
- 激励视频
- 信息流广告

### 广告策略

根据应用类型组合广告：

| 场景 | 建议策略 |
|---|---|
| 高频工具 | 横幅、操作完成后的低频插屏 |
| 内容应用 | 原生广告、信息流广告 |
| 娱乐应用 | 插屏、激励视频 |
| AI 或高成本功能 | 激励视频换取使用次数 |
| 订阅型效率应用 | 免费版少量广告，订阅后去广告 |

### 广告规则

- 付费用户默认不展示广告，特殊权益商品除外。
- 首次核心任务过程中不展示插屏广告。
- 插屏广告必须设置时间和次数间隔。
- 激励广告必须明确说明奖励内容。
- 广告加载失败不能阻塞核心流程。
- 奖励发放必须以服务端或可信回调为准。
- 支持按国家、版本、用户类型和渠道关闭广告。
- 支持多个广告平台的瀑布流或竞价策略。
- 记录展示、点击、填充、收益和广告关闭事件。

---

## 5.7 权益与额度中心

权益系统应与具体应用功能解耦。

### 权益示例

- `remove_ads`
- `unlimited_usage`
- `premium_templates`
- `cloud_sync`
- `export_hd`
- `priority_processing`
- `monthly_ai_credits`

### 功能要求

- 根据商品映射权益组合。
- 支持永久、周期和限次权益。
- 支持运营赠送。
- 支持补偿额度。
- 支持权益冻结、回收和恢复。
- 支持查看权益变更流水。
- 支持多应用共享权益或相互隔离。

初期建议默认采用“一应用一订阅”，避免用户理解和商店审核复杂化。待应用矩阵形成品牌后，再测试跨应用会员。

## 六、商业化方案

不同应用不应统一套用一种变现方式。

| 应用特征 | 推荐模式 |
|---|---|
| 使用频率高、成本低 | 广告 + 去广告订阅 |
| 专业价值高 | 订阅 |
| 功能稳定、持续成本低 | 买断 + 可选升级 |
| AI 调用成本高 | 订阅额度 + 消耗包 |
| 内容持续更新 | 订阅 + 部分免费内容 |
| 娱乐性强 | 广告 + 激励视频 |
| 低频刚需工具 | 买断或单次购买 |

### 定价建议

每个应用至少配置：

- 一个主推订阅套餐。
- 一个价格锚点套餐。
- 一个低门槛购买方案。
- 免费体验或有限免费额度。
- 远程可调整的付费墙展示策略。

不建议所有应用都默认使用周订阅。周订阅容易提高短期收入，但也可能带来退款、差评和审核风险。

## 七、数据指标与埋点

### 7.1 北极星指标

单个应用：

- 周有效任务完成用户数
- 每活跃用户有效任务次数
- 付费用户有效使用频率

应用矩阵：

- 单应用回本周期
- 90 天累计贡献利润
- 应用存活率
- 平台公共模块复用率
- 从立项到上线所需时间

### 7.2 核心漏斗

曝光  
→ 商店访问  
→ 下载  
→ 首次打开  
→ 完成引导  
→ 首次核心操作  
→ 获得有效结果  
→ 触达付费墙  
→ 发起支付  
→ 支付成功  
→ 次日／七日／三十日留存  
→ 续订

### 7.3 商业化指标

- 付费墙曝光率
- 付费墙转化率
- 试用开启率
- 试用转付费率
- 续订率
- 退款率
- 客单价
- ARPU、ARPPU
- LTV
- 广告展示率、填充率、eCPM
- 单用户广告收入
- 单次有效任务成本
- 毛利率
- 获客回收周期

### 7.4 实验能力

支持针对以下内容开展 A/B 测试：

- 新用户引导
- 付费墙样式
- 付费墙触发时机
- 套餐排序
- 价格与试用期
- 免费次数
- 广告频率
- 功能入口
- 推送文案

实验必须具备互斥分组、固定用户分桶、版本记录和停止开关。

## 八、非功能需求

### 性能

- 冷启动时间应控制在业务可接受范围内。
- 常规页面操作保持流畅。
- 远程配置需具备本地缓存。
- 后台任务支持中断恢复。
- 大文件和 AI 任务显示明确进度。

### 稳定性

- 核心功能崩溃率、支付成功率和接口可用性应单独监控。
- 支付、权益和奖励发放必须具备幂等机制。
- 配置错误能够快速回滚。
- 单个应用故障不得影响其他应用。

### 安全

- 敏感数据传输和存储加密。
- 服务端校验支付与关键权益。
- 管理后台实施角色权限控制。
- 关键操作保留审计日志。
- 防止免费额度刷取、支付伪造和广告奖励作弊。
- API 设置签名、限流和异常检测机制。

### 合规

- 提供隐私政策、服务条款及订阅说明。
- 明确展示自动续费价格、周期和取消方式。
- 支持用户查询、导出和删除个人数据。
- 未经同意不得采集非必要数据。
- 广告追踪遵循所在地区及平台授权要求。
- 儿童、健康和金融相关应用执行更严格的合规策略。
- 避免仅换皮、功能重复度过高的应用矩阵，以降低商店审核风险。

| 超级管理员 | 全部权限 |

## 十一、首期验收标准

- 能通过后台创建并配置一个新应用。
- 新应用可以复用账号、支付、订阅、广告和埋点模块。
- 支持至少月订阅、年订阅和永久买断。
- 支付成功后权益能够正确到账。
- 退款、过期和恢复购买能够正确更新权益。
- 免费与付费用户展示不同的功能及广告策略。
- 关键功能和商业化流程具备完整埋点。
- 远程配置支持灰度发布及回滚。
- 后台可按应用查看新增、留存、付费和广告收入。
- 完成首批 3～5 个应用上线，以验证平台复用效率。

## 十二、待确认事项

正式进入详细设计前，需要确定：

- 首批重点品类及 3～5 个种子应用。
- 主要市场、国家和目标语言。
- 优先支持 iOS、Android，还是双端同步。
- 自研比例与跨平台技术方案。
- 是否以订阅收入或广告收入为第一目标。
- 是否建设统一品牌及跨应用账号。
- AI 类功能是否包含模型调用成本。
- 内容版权、用户生成内容和审核机制。
- 单应用立项、止损及下架标准。
- 预计上线节奏和团队配置。
